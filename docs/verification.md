# Проверка Explorer Pro 0.2.0

Дата: 2026-10-06. Среда: macOS, установленное приложение `/Applications/Visual Studio Code.app`, VS Code 1.140.0 arm64, Node.js 22.

## Автоматические проверки

- `npm test`: 22 теста. История навигатора, повторные клики, границы и сокращение истории, вложенный фокус, перезапуск состояния, возврат к исходному saved multi-root workspace и пустому окну, отказ validate/write/open, отказ и отмена/отложенное применение восстановления, параллельные переключения и лимит истории.
- `npm run lint`: ESLint; `npm run compile`: TypeScript strict.
- `npm run test:host`: пять отдельных запусков установленного VS Code с изолированными user-data/extensions. Отдельная копия приложения не скачивалась.

## Что проверено в настоящем Extension Host

1. Навигатор: чтение каталога, скрытые файлы, ссылка на файл, Enter, Back/Forward/Up, повторные команды клика одного элемента, открытие и закрепление файла, повторное использование терминала, наличие всех заявленных команд. Подготовлен фокус на дочернюю папку.
2. Реальный VS Code открыт на подготовленном workspace: загружены нужная папка, исходный URI и состояние фокуса; подготовлен вложенный фокус.
3. На вложенном workspace: восстановилась история двух фокусов; подготовлен шаг назад.
4. После открытия предыдущего фокуса: курсор истории соответствует первой папке; подготовлен возврат к исходному `.code-workspace`.
5. После открытия исходного workspace: восстановлены оба именованных корня, режим фокуса выключен. Исходный файл workspace не изменился.

Адаптер `open` в тестовом процессе перехватывается для записи подготовленного destination, чтобы `vscode.openFolder` не уничтожил выполняемые проверки. Затем внешний официальный runner `@vscode/test-electron` открывает этот же destination настоящим VS Code. Таким образом проверены запись workspace, загрузка после нового запуска, регистрация и выполнение команд; непрерывное переключение окна командой `vscode.openFolder` и реальные мышиные двойные клики отдельно в GUI этим тестом не проверяются.

## Практические границы

Полная ручная приёмка GUI и сценариев Workspace Trust не проведена: сервис Computer Use вернул `Sky Computer Use service startup request failed`. Windows/Linux, remote workspace, несохранённые настройки untitled workspace и восстановление работающего терминала после перезапуска требуют дополнительных сценариев. Автоматическое обновление раскрытых вложенных каталогов и очистка старых служебных workspace находятся в roadmap.

## Выпуск

Пакет: `out/explorer-pro-0.2.0.vsix`. В пакет входят только манифест, локализация, документация расширения, ресурсы и исполняемые модули `out/`. Тесты, исходники, node_modules, тестовые профили и предыдущие VSIX исключаются.

VSIX установлен через официальный CLI в основной VS Code; проверен идентификатор `max-local.explorer-pro@0.2.0`. `npm audit` после обновления тестовых и сборочных зависимостей: 0 уязвимостей.
